# /write-review - マルチ視点ライティングレビュー

## 概要
文章を**複数の独立した視点**で体系的にレビューし、修正箇所を特定する。academic-research-skillsのmulti-perspective review + integrity gateをCmdC向けに最適化。

## レビュー視点（5視点 × 独立実行）

| 視点 | 役割 | チェック項目 | 出力 |
|------|------|-------------|------|
| **構造・論理** | Logical Editor | 論理飛躍・欠落・循環・重複・MECE | 構造図・論理ギャップ列挙 |
| **文体・表現** | Style Editor | 冗長・受動態・専門用語・リズム・接続詞 | 文体スコア・改善案 |
| **読者・UX** | Reader Advocate | 対象読者適合・認知負荷・アクション明確さ | 読者ジャーニー・阻害要因 |
| **事実・引用** | Fact Checker | 数値・引用・リンク・一次情報・鮮度 | ファクトチェック表・要修正箇所 |
| **整合性** | Integrity Gate | 自己矛盾・前後矛盾・約束事履行・トーン統一 | 整合性レポート・ゲート判定 |

## 使い方

```
/write-review <ファイル/テキスト>          # フルレビュー実行
/write-review --perspective=<視点>         # 特定視点のみ
/write-review --mode=<モード>              # モード指定
/write-review --threshold=<閾値>           # 指摘閾値設定
```

## モード

| モード | 視点数 | 深度 | 用途 |
|--------|--------|------|------|
| `quick` | 2 (構造+文体) | 浅い | 下書き段階・高速確認 |
| `standard` | 4 (構造+文体+読者+事実) | 標準 | 公開前・提出前 |
| `deep` | 5 (全視点+整合性) | 深い | 重要文書・論文・契約 |

## ワークフロー

### Phase 1: 入力解析
```
入力テキスト → セグメント分割(段落/セクション) → メタデータ抽出(文字数/構成/引用)
```

### Phase 2: 並列レビュー実行
```
5視点を独立エージェントで並列実行
各視点: ルールベース + LLM判定 → 指摘事項(JSON)出力
```

### Phase 3: 統合・優先度付け
```
全指摘マージ → 重複除去 → 重要度スコアリング → 修正優先度ランキング
重要度 = (視点重み × 発生頻度 × 影響範囲 × 修正容易性)
```

### Phase 4: レポート生成
```
出力形式:
  - サマリ (総指摘数/重要度分布/推定修正時間)
  - 詳細指摘一覧 (箇所/視点/重要度/現状/改善案/理由)
  - 修正版テキスト (指摘反映・差分表示)
  - チェックリスト (次回レビュー用)
```

## 視点別ルールベース（抜粋）

### 構造・論理 (Logical Editor)
- [ ] 論理構造: 導入→本論→結論 / PREP / SDS / STAR いずれか準拠
- [ ] MECE: 重複なく漏れなく分類されているか
- [ ] 論理飛躍: 前提→結論の間に欠落ステップがないか
- [ ] 循環論証: 結論を前提にしていないか
- [ ] 一貫性: 用語定義・前提条件が文書内で統一されているか

### 文体・表現 (Style Editor)
- [ ] 接続詞過多: 「また」「さらに」「しかし」が同段落3回以上
- [ ] 受動態過多: 能動態に書き換え可能な受動態が50%以上
- [ ] 冗長表現: 「～することができる」→「できる」等の簡略化可能
- [ ] 専門用語: 対象読者に未定義の専門用語がないか
- [ ] リズム: 文長・句読点間隔に変化があるか

### 読者・UX (Reader Advocate)
- [ ] 対象明確: ターゲット読者が冒頭で明示/推定可能か
- [ ] 認知負荷: 新概念導入時に定義・類比・図解があるか
- [ ] アクション: 読後期待アクション（理解/実行/判断/共有）が明確か
- [ ] スキャン性: 見出し・箇条書き・太字で要点把握可能か

### 事実・引用 (Fact Checker)
- [ ] 数値: 統計・データに出典・取得日・信頼度明記
- [ ] 引用: 文献・URL・発言に正確な参照（著者/タイトル/年/ページ/URL）
- [ ] リンク: 外部リンクが生存・関連・権威あるか
- [ ] 一次情報: 二次・三次情報の連鎖で一次まで遡れるか
- [ ] 鮮度: 情報の陳腐化リスク・最終更新日確認

### 整合性 (Integrity Gate)
- [ ] 自己矛盾: 同一主張の異なる箇所で内容食い違いなし
- [ ] 前後整合: 前提→展開→結論の流れで矛盾なし
- [ ] 約束履行: 冒頭で宣言した構成・範囲・成果物を全て履行
- [ ] トーン統一: 文体・敬語・一人称・専門用語レベルが統一

## オプション

| オプション | 説明 | デフォルト |
|-----------|------|-----------|
| `--perspective` | 実行視点 (structure/style/reader/fact/integrity/all) | all |
| `--mode` | モード (quick/standard/deep) | standard |
| `--threshold` | 重要度閾値 (low/medium/high/critical) | medium |
| `--output` | 出力形式 (md/json/html/annotated) | md |
| `--auto-fix` | 軽微指摘(表記揺れ/タイポ等)自動修正版も出力 | false |
| `--save` | 結果をObsidian/Notion保存 | false |

## 品質基準
- **独立性**: 各視点が他視点に依存せず実行可能
- **完全性**: 既知の文章品質問題を網羅的に検出
- **実行可能性**: 指摘に具体的改善案・修正箇所付与
- **学習**: ユーザー修正パターンを蓄積し精度向上
