# /tdd - TDD統合ワークフロー

## 概要
**Test-Driven Development (TDD)** の RED-GREEN-REFACTOR サイクルを強制・支援。テストファーストでの機能開発・バグ修正・リファクタリングを体系的に実行。

## 使い方

```
/tdd <機能説明>                    # 新機能TDD開始
/tdd --fix <バグ説明>               # バグ修正TDD (再現テスト→修正)
/tdd --refactor <対象>              # リファクタリングTDD (既存テスト保護)
/tdd --continue                     # 中断セッション再開
/tdd --status                       # 現在のサイクル状態表示
```

## TDDサイクル (厳格実行)

### RED Phase (失敗するテスト書く)
```
入力: 要求仕様 / バグ再現条件 / リファクタ対象
処理:
  1. 受け入れ基準をテストケースに変換
  2. 最小限の失敗テスト作成 (コンパイルエラー含む)
  3. テスト実行 → 赤確認 (失敗メッセージ確認)
  4. テスト名・意図・期待値をドキュメント化
出力: 失敗テストコード + 仕様メモ
品質ゲート: テストが「正しい理由で失敗」していること
```

### GREEN Phase (最小実装で通す)
```
入力: 失敗テスト
処理:
  1. テストを通す最小・最速・最汚い実装
  2. ハードコード・仮実装・部分実装許容
  3. テスト実行 → 緑確認
  4. 他テストへの副作用確認 (回帰なし)
出力: 動作する実装コード
品質ゲート: 対象テストのみ通過・他テスト壊さない
```

### REFACTOR Phase (綺麗にする)
```
入力: 動作する実装 + 全テスト緑
処理:
  1. コード臭検出 (重複/長メソッド/巨大クラス/プリミティブ執着等)
  2. リファクタリング適用 (Extract Method/Inline/Rename/Move等)
  3. 各ステップ後に全テスト実行 → 緑維持確認
  4. 設計原則確認 (SOLID/DRY/YAGNI/KISS)
出力: クリーンな実装コード
品質ゲート: 全テスト緑・カバレッジ維持・複雑度低下
```

## モード別フロー

| モード | 入力 | RED | GREEN | REFACTOR | 用途 |
|--------|------|-----|-------|----------|------|
| `feature` | 機能説明 | 受け入れ基準→テスト | 最小実装 | 設計適用 | 新機能開発 |
| `bugfix` | バグ報告 | 再現テスト | 修正 | 再発防止テスト追加 | バグ修正 |
| `refactor` | 対象コード | 既存テスト確認 | - | 段階的改善 | リファクタリング |

## オプション

| オプション | 説明 | デフォルト |
|-----------|------|-----------|
| `--mode` | モード (feature/bugfix/refactor) | feature |
| `--test-framework` | テストFW (jest/vitest/pytest/mocha/go-test) | 自動検出 |
| `--coverage` | カバレッジ目標 (%) | 80 |
| `--watch` | ウォッチモード (ファイル変更時自動実行) | false |
| `--no-refactor` | REFACTORフェーズスキップ | false |
| `--max-cycles` | 最大サイクル数 (無限防止) | 10 |
| `--commit-each` | サイクル毎にコミット | false |

## 実行例

### 新機能開発
```
/tdd "ユーザー登録API: email/passwordで登録、JWT返却、重複チェック"
# → RED: 登録成功/重複エラー/バリデーションエラーのテスト作成
# → GREEN: 最小実装 (ハードコードから開始)
# → REFACTOR: バリデーション分離・エラーハンドリング統一・型安全化
```

### バグ修正
```
/tdd --fix "ログイン時、パスワードリセットトークンが期限切れでもエラーにならない"
# → RED: 期限切れトークンで400返すテスト作成 (現状200)
# → GREEN: トークン検証ロジックに期限チェック追加
# → REFACTOR: トークン検証を共通ユーティリティ化・テスト追加
```

### リファクタリング
```
/tdd --refactor "src/services/auth.ts の責務分離"
# → 既存テスト全緑確認
# → 責務ごとにクラス分割 (TokenService/UserService/ValidationService)
# → 各ステップでテスト実行・緑維持
```

## 統合ツール連携

| ツール | 連携内容 |
|--------|----------|
| `jest/vitest` | テストランナー・ウォッチ・カバレッジ |
| `tsc --noEmit` | 型チェック (GREEN/REFACTOR各ステップ) |
| `eslint/biome` | Lint (REFACTORステップ) |
| `git` | --commit-each時: RED/GREEN/REFACTOR各コミット |
| `coverage` | カバレッジレポート・未カバー行ハイライト |

## 品質ゲート (各フェーズ必須)

| フェーズ | ゲート条件 | 違反時 |
|----------|-----------|--------|
| RED | テストが「正しい理由」で失敗 | 仕様確認・テスト修正 |
| GREEN | 対象テストのみ通過・回帰なし | 実装見直し・スコープ縮小 |
| REFACTOR | 全テスト緑・カバレッジ維持・複雑度↓ | リファクタリング中止・元に戻す |

## 学習・蓄積
- サイクル時間・失敗理由・リファクタリングパターンを履歴化
- プロジェクト固有の「よくあるRED失敗」ナレッジベース化
- カバレッジ傾向・テスト品質メトリクス追跡
