# session-kickoff — 雛形集（FORMS）

session-kickoff の各フェーズで使うテンプレート。SKILL.md から参照される。
コピーして埋める。**埋めるのはメインセッション（PM）**。サブエージェントには渡さない。

---

## 1. プラン雛形（Phase 5 — `plans/<task>.md`）

```markdown
---
task: "<タスク名>"
created: YYYY-MM-DD
status: 進行中
version: 1.0.0
---

# <タスク名> — プラン（生きた文書）

## ゴール
<要望を1文で>

## 合格条件（検証可能）
- [ ] <検証可能な条件1>
- [ ] <検証可能な条件2>

## 現状
<現在地 / 完了 / 未完了>

## WBS（タスク分解）
| ID | タスク | 想定コスト | 依存 | 状態 |
|----|--------|-----------|------|------|
| T1 | <おおまかな作業単位> | S/M/L | - | 未着手 |
| T2 | <…> | S | T1 | 未着手 |

## セッション分割
- セッション1: <範囲>（コンテキスト残量50-60%で切る）
- セッション2: <範囲>

## 新事実・決定ログ
- YYYY-MM-DD: <発見した事実・決定>

## 次にやること
- <次セッションの最初のアクション>
```

## 2. タスクブリーフ雛形（Phase 4・委譲時に必ず添付）

```markdown
## Objective
<このサブエージェントが達成すべきこと>

## Do（やること）
- チャネル: <official-docs / github / reddit / x>
- 調査項目: [具体的リスト]
  - 項目1
  - 項目2

## Don't（やらないこと）
- 実装を始めない。結論（サマリー）だけ返す
- このタスクの範囲外のファイル・タスクを読まない/触らない
- 不確かな主張にソースを付けない（付けられないなら「未検証」と明記）

## Deliverable（戻す成果物・形式）
- 形式: 構造化サマリー（<500トークン>）
- 引用: 必ずURL

## 予算
- max_turns: <6（調査）/ 8（レビュー）>
- 要約トークン上限: <500>
- effort: <low / medium / high>
```

## 3. WBS雛形（Phase 3）

```markdown
## WBS
| ID | タスク | 想定コスト(S/M/L) | 依存 | 並列可否 | 詳細 |
|----|--------|------------------|------|---------|------|
| T1 | ゴール定義・合格条件 | S | - | 不可(逐次) | Phase1 |
| T2 | リサーチ: 公式Doc | S | T1 | 可(並列) | Phase4 |
| T3 | リサーチ: GitHub | S | T1 | 可(並列) | Phase4 |
| T4 | プラン策定 | M | T2,T3 | 不可(逐次) | Phase5 |
```

## 5. 引継ぎ雛形（Phase 7 — 2つの単一情報源）

Phase 7 では **タスク計画** と **セッション状態** の2つを分けて更新する。

### 5-a: タスク計画への追記（`plans/<task>.md`）

```markdown
## 引継ぎ（YYYY-MM-DD HH:MM）
- **立ち位置**: <WBSのどこまで進んだか>
- **完了**: <完了したタスク>
- **未完了**: <未完了のタスク>
- **次にやること**: <次セッションの最初のアクション>
- **開いたままの決定事項**: <未解決の判断>
```

### 5-b: セッション状態（Obsidian `sessions/<topic>.md`）

無ければ `sessions/_TEMPLATE.md` から作成。`session-router.md` の status も flip する。

```markdown
## ゴール
<セッション/タスクのゴールを1文で>
## 進捗（完了）
- <完了したこと>
## 未完了
- <未完了のこと>
## 次アクション
- <次セッションの最初のアクション>
## 決定事項
- <確定した・開いたままの決定>
## changelog
- YYYY-MM-DD: <最新の変更を上に>
```
