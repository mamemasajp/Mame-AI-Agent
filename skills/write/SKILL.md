# /write - 反復改善ライティングワークフロー

## 概要
個人報告書・ブログ記事・SEO記事・技術文書など、**あらゆる文章作成**を「書く→フィードバック→改善」の反復サイクルで品質を段階的に向上させます。ユーザーの書き味を学習し、文脈に合わせた最適な支援を行います。

## 使い方

```
/write                    # 対話式で執筆開始
/write <テーマ>            # テーマ指定で開始
/write --type=<種類>       # 種類指定 (report|blog|seo|tech|email|doc)
/write --draft=<ファイル>   # 既存下書きから改善
```

## ワークフロー

### Phase 0: 要件確認
```
- 目的・ターゲット・トーン・長さ・構成要件の明確化
- 参照資料・参考文献の収集
- 成功基準の合意（読了率、CV率、技術正確性等）
```

### Phase 1: 構成・アウトライン生成
- 論理構成案の提示（導入→本論→結論）
- 見出し構造・キーワード配置計画
- ユーザー承認後に次へ

### Phase 2: 初稿執筆
- 構成に従いセクションごと執筆
- 要所でユーザー確認ポイント設置
- 完成したら全文提示

### Phase 3: フィードバック・改善ループ
```
ユーザーFB取得 → 改善案提示 → 適用確認 → 反映 → 再提示
```
- **FB種類**: 構成/論理/文体/専門用語/説得力/可読性
- **改善単位**: 段落/セクション/全体
- **収束条件**: ユーザー「これでOK」または上限回数(5回)

### Phase 4: 最終仕上げ
- 文法・表記揺れ・リンク切れチェック
- SEO/アクセシビリティ最適化（該当時）
- 納品形式出力（Markdown/HTML/PDF等）

## 記事タイプ別プリセット

| タイプ | 構成テンプレ | 重点ポイント | 成功指標 |
|--------|-------------|-------------|----------|
| `report` | 要旨→背景→手法→結果→考察→結論 | 客観性・根拠・再現性 | 決定者が即判断可能 |
| `blog` | フック→共感→本論→気づき→CTA | 親近感・ストーリー・実用性 | 読了率・シェア率 |
| `seo` | キーワード導入→網羅的解説→FAQ→まとめ | 検索意図網羅・E-E-A-T | 順位・滞在時間 |
| `tech` | 概要→前提→実装→検証→運用→参考 | 正確性・再現性・保守性 | 実装者が迷わず動かせる |
| `email` | 結論ファースト→背景→アクション→締め | 簡潔・アクション明確 | 返信率・アクション実行率 |
| `doc` | 目的→前提→仕様→API→例→運用 | 完全性・検索性・バージョン管理 | 開発者が即参照可能 |

## オプション

| オプション | 説明 |
|-----------|------|
| `--type` | 記事タイプ指定 (report/blog/seo/tech/email/doc) |
| `--draft` | 既存ファイルから改善開始 |
| `--outline-only` | アウトラインのみ生成 |
| `--target-words` | 目標文字数 |
| `--tone` | トーン指定 (formal/casual/technical/persuasive) |
| `--audience` | ターゲット層 (executive/engineer/general/beginner) |
| `--iterations` | 最大改善ループ回数 (default: 5) |
| `--learn` | 完了後に書き味を学習 |

## 品質基準
- **Think Before Writing**: 書く前に構成・論理をユーザーと合意
- **Simplicity First**: 余計な修飾・冗長表現を削る
- **Surgical Edits**: 指摘箇所のみピンポイント修正
- **Goal-Driven**: 合意した成功基準で完了判定
