# /codebase-design - 深層モジュール設計支援

## 概要
**深層モジュール**設計のための共通語彙とチェックリストを提供。モジュールのインターフェース・実装分離、シームの位置、テスタビリティ、AIナビゲータビリティを体系的に評価・改善。

## 設計概念・語彙

| 概念 | 定義 | 良い例 | 悪い例 |
|------|------|--------|--------|
| **深層モジュール** | インターフェースは単純、実装は複雑・高機能 | `hash(password) → string` 内部でbcrypt/argon2/salt/pepper | `hash(password, algorithm, salt, rounds, pepper) → string` |
| **浅層モジュール** | インターフェースが複雑、実装が薄い | - | 単なるラッパー・委譲のみ |
| **情報隠蔽** | 実装詳細を外部に見せない | プライベートフィールド・内部関数 | パブリックフィールド・内部構造露出 |
| **シーム** | 実装を差し替え可能な境界 | インターフェース・DI・戦略パターン | 具象クラス直接依存・静的メソッド |
| **テスタビリティ** | 単体テスト容易性・モック不要度 | 純粋関数・依存注入・決定論的 | グローバル状態・副作用・外部IO |
| **AIナビゲータビリティ** | AIがコード理解しやすい構造 | 命名規則・型・ドキュメント・小さなファイル | 暗黙の規約・巨大ファイル・動的メタプログラミング |

## チェックリスト: モジュール設計レビュー

### インターフェース設計
- [ ] **単一責任**: 1つの概念のみを抽象化しているか
- [ ] **最小インターフェース**: 呼び出し側が知る必要最小限か
- [ ] **安定性**: 変更頻度が低く、依存されやすいか
- [ ] **自己完結**: 型定義・エラー・設定が内包されているか

### 実装・情報隠蔽
- [ ] **実装分離**: インターフェースファイルと実装ファイルが分離されているか
- [ ] **プライベート実装**: 内部関数・定数・状態が外部から触れないか
- [ ] **依存方向**: 抽象に依存し、具象に依存していないか (DIP)
- [ ] **副作用局所化**: IO・状態変更・時間・乱数が境界に閉じ込められているか

### シーム・拡張性
- [ ] **戦略注入**: アルゴリズム・ポリシー・ストレージ等が差し替え可能か
- [ ] **ファクトリ・ビルダー**: 複雑な生成ロジックが隠蔽されているか
- [ ] **イベント・フック**: 重要な状態変化で外部通知できるか
- [ ] **設定外部化**: 魔法の数値・閾値・タイムアウトが設定可能か

### テスタビリティ
- [ ] **純粋関数比率**: ビジネスロジックの純粋関数化率 ≥ 70%
- [ ] **依存注入**: 外部依存(DB/HTTP/時刻/乱数)がインターフェース経由か
- [ ] **決定論的**: 同一入力で常に同一出力 (副作用なし)
- [ ] **高速実行**: 単体テストが10ms以内・並列実行可能
- [ ] **モック不要**: 実装依存のモックを書かずにテスト可能

### AIナビゲータビリティ
- [ ] **命名**: 意図が伝わる名 (動詞=コマンド/クエリ、名詞=エンティティ/VO)
- [ ] **型**: 入出力・状態・エラーが静的型で表現されているか
- [ ] **ドキュメント**: なぜこの設計か・不変条件・使用例がコード近傍にあるか
- [ ] **ファイルサイズ**: 1ファイル ≤ 200行・1関数 ≤ 50行
- [ ] **依存グラフ**: 循環なし・層状・明確な階層

## コマンド

### 設計評価
```
/codebase-design evaluate src/auth/                    # ディレクトリ評価
/codebase-design evaluate src/auth/session.ts          # ファイル評価
/codebase-design evaluate --module=AuthService         # モジュール名指定
```

### 語彙・定義
```
/codebase-design vocab                                   # 用語集表示
/codebase-design vocab deep-module                       # 定義詳細
/codebase-design vocab seam                              # シームパターン集
```

### 改善提案
```
/codebase-design suggest src/payment/                    # 改善提案
/codebase-design suggest --focus=testability             # テスタビリティ特化
/codebase-design suggest --focus=ai-nav                  # AIナビゲーション特化
```

### テンプレート生成
```
/codebase-design template module --name=UserService      # モジュール雛形
/codebase-design template interface --name=PaymentGateway # インターフェース雛形
/codebase-design template test --for=OrderService        # テスト雛形
```

## 出力例: 評価レポート

```
## Codebase Design Evaluation: src/auth/

### Summary
- **深層度スコア**: 72/100 (良好)
- **テスタビリティ**: 65/100 (要改善)
- **AIナビゲータビリティ**: 78/100 (良好)

### Strengths
✅ AuthServiceインターフェースは単純 (login/logout/refresh のみ)
✅ PasswordHasher戦略パターンで差し替え可能 (シーム良好)
✅ 型定義・エラー型が充実 (AIナビゲーション良好)

### Issues
⚠️ **SessionRepository が具象実装に依存** (DIP違反)
   - 修正: Repositoryインターフェース抽出・DI
⚠️ **JWT秘密鍵がハードコード** (設定外部化不足)
   - 修正: Configインターフェース経由で注入
⚠️ **login() に副作用混在** (ログ・メトリクス・DB書き込み)
   - 修正: ドメインイベント発行に分離・副作用を境界へ

### Suggestions
1. `AuthServiceInterface` 抽出し、実装を `AuthServiceImpl` に分離
2. `SessionRepositoryInterface` 定義し、DIコンテナで束縛
3. `LoginResult` ドメインイベント (`UserLoggedIn`) 発行に変更
4. 純粋関数 `validateCredentials` 抽出し、テスト容易化
```
