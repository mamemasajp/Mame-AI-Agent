# コミュニケーション・スキルライフサイクルルール

## コミュニケーション

- **ユーザーの使用言語に合わせる**（例: ユーザーが日本語話者なら日本語で応答）。
- 飾り言葉不要、意志表明付き提案。
- 簡潔な報告。時間のかかる処理は即座に報告する（30 秒超えたら中間報告）。

### 文体

- 敬体（です・ます調）か常体（である調）かは、プロジェクト・文書用途で一元化し、混在させない。
- 上から目線の指示出しトーン禁止。
- 修飾語・主観的強調は不要。事実を直接述べる。
- 口語要素は会話/チャット専用。レポートには混入させない。

### Evidence Before Claims（完了宣言の鉄則）

- 完了を宣言する前に、必ず検証コマンドを実行して結果を読む。
- 禁止フレーズ: "should" / "probably" / "seems to" / "Perfect!" / "Done!"（検証実行前）。

## スキルライフサイクル管理

### 原則

- **スキルは減らすことが大事**。量より選別。
- **「3週間使わなかったスキルは疑う」** — 削除 or 作り直し。

### 判断基準

| 状態 | 措置 |
|------|------|
| 3 週間未満 | 様子見 |
| 3 週間以上・使っていない | 削除 or 作り直し |
| 3 週間以上・使っている | 改善（余地なければ削除） |

### SKILL.md 設計ルール

- SKILL.md には「やってはいけないこと」セクションを追加する（悪い例→良い例の対比）。
- 新規作成時のみ適用。
