# Git ワークフロールール

## 基本原則

- **メイン(デフォルト)ブランチでの作業禁止** — 常に作業ブランチを作成してから作業する。
- メインにいることに気づいたら、即座に `git checkout -b <種類>/<内容>` で離脱する。
- メインへの直接 commit/push 禁止。身内プロジェクトであっても徹底する。

## ブランチ名

基本形式: `<種類>/<内容>` のケバブケース

| 種類 | 用途 |
|------|------|
| `feature/` | 新機能追加 |
| `fix/` | 不具合修正 |
| `refactor/` | リファクタリング（仕様不変） |
| `docs/` | ドキュメント修正 |
| `chore/` | 環境設定・雑務 |
| `backup/` | バックアップ（日付サフィックス必須） |

例: `feature/add-login`, `fix/typo-homepage`, `chore/update-config`

## コミットメッセージ

`<prefix>: <理由>、<内容>` — Conventional Commits 準拠

Prefix: feat / fix / docs / style / refactor / perf / test / chore
- 「何を」ではなく**なぜ**を書く
- 形式: `feat: 〇〇なため、△△を追加（add △△ for 〇〇）`
- 言語はプロジェクトで一元化（日本語 or 英語、混在させない）

## PR 作成は自動化しない

- PR はユーザーの明示指示があった場合のみ作成する。自律判断・自動実行しない。
- commit + push まで自動実行 → PR 作成は確認（y/N）。
- 「親切心」が将来の事故の種。ルールとして機械的に守る。

## 複数タスクの分離（推奨パターン）

- **1 セッション = 1 ブランチ**（WIP=1）を基本とする。
- 並列作業が必要な場合は git worktree を使う（例: `.worktrees/feature/<name>/`）。
- ブランチ完了時は作業ブランチを削除し、worktree も片付ける。
- 未コミット変更があれば、削除・破棄前に確認する。
- この推奨は「プロジェクト固有ツールありき」ではない。環境に合わせて読み替えること。
