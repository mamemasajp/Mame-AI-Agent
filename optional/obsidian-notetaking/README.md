# Obsidian 運用方法（抽象化リファレンス）

> AI エージェントで Obsidian（ローカルMarkdownノート）を運用するための**汎用的な方法論**をまとめたリファレンスです。
> 個人固有名や絶対パスは含めず、「AI エージェント利用者なら誰でも」読める形に抽象化しています。Vault の絶対パスは `${OBSIDIAN_VAULT}` プレースホルダで表現します。
>
> 関連する実行スキル: [`inbox-organize`](../inbox-organize/)、[`session-kickoff`](../session-kickoff/)、[`mid-point`](../mid-point/)、[`session-end`](../session-end/)

## この文書の位置づけ

Obsidian は「Markdown のファイルがそのまま知識ベースになる」シンプルなツールです。AI エージェントと組み合わせると、収集 → 整理 → 検索 → 出力 のサイクルを自動化できます。本リファレンスはその**ディレクトリ構造・命名・メタデータ運用**を体系化したものです。エージェント（Claude Code 等）のスキルから参照する前提で書いています。

## 1. PARA 構造

情報を「アクション可能性」と「ライフサイクル」で分類する運用の基本形です。Obsidian 用に `00-Archive` 相当を足した **6 領域 + Inbox** が実用的です。

| 領域 | 役割 | 判断基準（いつ置くか） |
|------|------|------------------------|
| `${OBSIDIAN_VAULT}/00-Inbox/` | **未整理の溜め場（Raw RAM）** | 何でも。乱雑でOK。ここへぶち込む |
| `${OBSIDIAN_VAULT}/10-Projects/` | **期限・ゴールのある作業** | 完了条件・期限・ステークホルダーが明確なもの |
| `${OBSIDIAN_VAULT}/20-Areas/` | **継続的責任（分野別）** | 期限はないが継続して管理する責任領域 |
| `${OBSIDIAN_VAULT}/30-Resources/` | **参照・知識・素材** | 他で参照する記事・論文・仕様・テンプレ |
| `${OBSIDIAN_VAULT}/40-Archive/` | **完了・非アクティブ** | 完了プロジェクト・古い資料・参考済み |
| `${OBSIDIAN_VAULT}/99-Meta/` | **システム・設定・ログ** | 設定・スクリプト・整理ログ・メタ情報 |

### 分類の考え方
- **Project（期限あり）** vs **Area（責任の継続）** を明確に分けるのが肝. 期限のある作業は Project、それ以外の「ずっと守る領域」は Area。
- **Inbox は常に受付口**。いきなり永続ディレクトリへ配置せず、まず Inbox に置き、後で人間（またはエージェント）が整理する。

## 2. ファイル命名

機械が扱いやすく、時系列で並ぶ命名を標準にする。

```
<YYYY-MM-DD>_<タイトル>.md
```

- 先頭に **日付（ISO 形式）** を置くと、ファイルエクスプローラ・`ls` で自然な時系列順に並ぶ
- タイトルは「何のノートか」を一意に表す短い語句
- 日付のないテーマ性ノートでも統一したい場合は `00-` 等のソートプレフィックスを使う

## 3. frontmatter（YAML）

機械的な分類と検索のため、全ノートに最小のメタデータを持たせる。

```yaml
---
title: "<タイトル>"
date: <YYYY-MM-DD>
tags:
  - type/<note|plan|report|reference|meta|...>
  - status/<draft|active|done|...>
  - area/<life|dev|ai|...>   # 必要に応じて
---
```

3 つの推奨タグ体系:
- **`type/*`** — ノートの種類（分類の主キー）
- **`status/*`** — ライフサイクル状態（整理・検索のフィルタ用）
- **`area/*`** / **`topic/*`** — 分野・テーマ（横断検索用）

これらを frontmatter に持たせることで、エージェントは「タグを読むだけで配置先・状態を判断」できる（`inbox-organize` がこの方式を利用）。

## 4. AI エージェントとの運用ループ

```
収集(00-Inboxへ) → 整理(inbox-organizeでPARAへ) → 検索(タグ/グラフ) → 出力(レポート/プラン) → 保存(session-end/mnemon)
```

- **収集**: 何でも 00-Inbox へ（乱雑でOK）
- **整理**: 内容を確認して PARA へ自動振り分け（`inbox-organize`）
- **検索**: frontmatter タグ + 本文の類似度（Obsidian グラフ）で横断
- **保存**: セッション終了時に状態を `99-Meta` / 記憶 MCP へ書き戻す（`session-end`）

## 5. 導入・プレースホルダ

Vault の絶対パスは環境により異なります。このリポジトリでは `${OBSIDIAN_VAULT}` プレースホルダで表現しており、自分の環境の実値へ置き換えて使います。

| プレースホルダ | 意味 | 設定例 |
|---------------|------|--------|
| `${OBSIDIAN_VAULT}` | Obsidian Vault のルート絶対パス | `/mnt/c/Users/<you>/ObsidianVault`・`/Users/<you>/ObsidianVault` 等 |

## 6. 秘密・個人情報ポリシー

本リファレンスと関連スキルには、実キー・固有名・絶対パスは含めません。Vault の実パスや個人設定は自分の環境でのみ使い、リポジトリへはプレースホルダのみ置きます（`lint-secrets.sh` が監視）。
